# Render: ограничения бесплатного размещения

Официальная документация Render указывает, что бесплатный Web Service останавливается после 15 минут отсутствия входящего HTTP- или WebSocket-трафика. Следующий запрос запускает сервис снова; запуск обычно занимает около минуты. Для Telegram webhook это означает, что первое событие после простоя может быть обработано с задержкой и потребовать повторной доставки Telegram.

Локальная файловая система бесплатного сервиса является эфемерной: данные теряются при перезапуске, redeploy и остановке. Поэтому приложение использует внешнее объектное хранилище для вложений и не сохраняет пользовательские файлы локально. База данных текущего проекта Manus не переносится в Render автоматически; без отдельной production-базы Render-версия не сможет использовать существующую MySQL-схему.

| Риск бесплатного Render | Мера в проекте | Оставшееся ограничение |
|---|---|---|
| Остановка после 15 минут простоя | Telegram повторяет недоставленные webhook-обновления; обработчик идемпотентно обновляет статусы | Возможна задержка первого события после простоя |
| Эфемерный диск | Фото, чеки, обложки и Excel сохраняются в объектном хранилище | Нужны корректные production-ключи хранилища |
| Нет переноса текущей базы | Схема Drizzle и миграции находятся в репозитории | Требуется совместимая внешняя MySQL/TiDB база и `DATABASE_URL` |

Источник: [Render — Deploy for Free](https://render.com/docs/free)

# «Добрые дела»: Telegram-native product direction

## Главная мысль продукта

«Добрые дела» — это не доска задач и не соревнование ради баллов. Это тёплый, ясный корпоративный ритуал: человек видит, **что сделать сейчас**, понимает, **зачем это команде**, и получает бережное признание только после реального подтверждения результата.

## Дизайн-язык

Визуальный характер: **редакционная теплота + Telegram-native скорость**. Основой становятся глубокий еловый цвет, молочная бумага, тёплый лимонный акцент и спокойный голубой для статусов ожидания. Карточки работают как небольшие «письма от команды»: контрастный заголовок, короткая мысль, одно понятное действие.

| Элемент | Решение |
|---|---|
| Тон сообщений | Тёплый, уважительный, конкретный. Сначала факт и следующий шаг, затем признание. |
| Markdown в боте | Короткий заголовок в жирном, смысловые акценты, воздушные абзацы; никогда не форматировать пользовательский ввод без escaping. |
| Emoji | Стандартные emoji как универсальный fallback. Custom/premium emoji используются лишь при явной технической конфигурации собственных ID бота; чужие ID не копируются и не вшиваются. |
| Интерактивность | Одна главная кнопка в сообщении; вторичные действия — рядом, но не конкурируют. Callback получает короткое подтверждение. |
| Mini App | Мобильный, учитывающий тему Telegram и safe areas. Ключевые действия сопровождаются лёгкой haptic-реакцией, если API доступен. |
| Анимация | Только transform/opacity, 120–220 мс, поддержка reduced motion. Движение подчёркивает переход, а не отвлекает. |

## Сценарии, которые становятся «живыми»

1. **Первый вход.** Не «заполните форму», а короткий маршрут с обещанием времени и понятным результатом.
2. **Открытие периода.** Участник получает контекст, настроение периода и кнопку в свой список задач.
3. **Новое задание.** Сообщение отвечает на вопросы «что», «какая награда», «что будет дальше», не выдавая баллы до проверки.
4. **Отчёт.** Каждый шаг сообщает прогресс, а отправка на проверку закрывает действие спокойным ожиданием.
5. **Решение P&C.** Подтверждение — это признание вклада и следующая возможность; доработка — ясная, не обвиняющая инструкция.
6. **Статистика.** Первый экран показывает личный следующий шаг, текущий ритм и командный контекст до рейтинга.

## Границы

- Для всех подтверждённых участников сохраняется одинаковый набор и количество заданий в периоде.
- Баллы начисляются только после явного решения P&C/Chief, а не за отправку отчёта или открытие интерфейса.
- Система не использует таймеры процесса Render Free; коммуникации остаются событийными или ручными.
- Main Mini App, профильные превью и custom emoji требуют отдельной настройки владельцем в BotFather; приложение готовится к этому без зависимости от неё.
